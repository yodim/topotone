# Contributing to Topotone

Thanks for stopping by. Topotone is small on purpose, and meant to be read, forked and extended. This page covers getting it running, the few rules that keep the world seamless, and two walkthroughs: adding a style, and tuning how the music becomes land.

Everyone taking part is expected to follow the [code of conduct](CODE_OF_CONDUCT.md).

## Getting started

You need Node 22 or newer.

```
npm ci
npm run dev        # http://localhost:5173/
```

The landscape starts on its own. Drop a song on the page or press Mic to give it sound. `D` shows the feature meters and the frame rate, and `?speed=4` in the address runs the landscape's own music four times faster.

Before a pull request:

```
npm run lint       # eslint and prettier (npm run format fixes most of it)
npm run typecheck
npm run test       # unit tests
npm run build
npm run test:e2e   # browser tests, for anything that draws or that you can click
```

The browser tests need Chromium: run `npx playwright install chromium` once, or point `PLAYWRIGHT_CHROMIUM_PATH` at a Chromium you already have.

## How it fits together

```
audio source ──► feature frames ──► mapping ──► generator ──► layer chunks ──► engine ──► style
(file, mic,      (pure data,        (music to   (seeded,       (pure data,      (camera,    (draws
 synthetic)       values 0..1)       intents)    deterministic)  no colors)       caching)    pixels)
```

Three small contracts hold it together:

- `src/audio/features.ts`: every source (a song, the mic, the landscape's own music) emits the same feature frames. The world never sees raw audio.
- `src/world/scene.ts`: what the generator makes and every style draws. Ridges, trees, water and sky described as shapes and roles, never as colors.
- `src/styles/types.ts`: the `Style` interface.

Changes to a contract are discussed in an issue first.

## The rules that keep it working

- **The same seed and the same music give the same world**, pixel for pixel, live and in the panorama export. All randomness goes through `src/core/rng.ts`. No `Math.random()`, `Date.now()` or `performance.now()` in `src/world/` or `src/styles/`; ESLint checks this.
- **Seamless by construction.** Every value is a function of the seed, the layer, the music time and the features nearby, never of state left over from the chunk before. That is what keeps chunk edges invisible.
- **The music steers, the noise draws.** Features set the large shapes. Seeded noise adds the detail.
- **Styles only draw**, and generation never knows styles exist.
- **No runtime dependencies** without asking first in an issue. The PRNG, the noise, the FFT, the textures and even the GIF encoder for the README are written here, which also makes the code a good read.
- **No binary textures and no audio files** in the repository. Textures are generated in code, and test audio is generated by `tests/fixtures/signals.ts`.
- **Audio stays on the device.** No network calls, no analytics, no uploads.

## Walkthrough: add a style

A style receives the same world as every other style and paints it its own way. Each one is inspired by a technique (woodcut, watercolor, risograph), never a copy of a specific artwork.

1. **Copy the template.** `cp -r src/styles/_template src/styles/charcoal`, then set `id: 'charcoal'` in `src/styles/charcoal/index.ts`. The folder name is the style id, and the registry finds the style by itself.
2. **Open it.** `npm run dev`, then `http://localhost:5173/?style=charcoal`. You get flat silhouettes, a gradient sky and a little mist. Replace one part at a time.
3. **The sky.** `drawSky(ctx, sky, view)` runs every frame, so keep it cheap: a gradient is fine, per-pixel work is not. A sky that changes slowly can live in a `ViewCache` from `styles/shared/canvas.ts`, repainted only when its colors move by a visible step. `sky` tells you the mood (calm to dramatic), brightness (dusk to day), cloudiness, mist and warmth.
4. **Textures.** Build them once in `setup(env)`, from `env.seed` (`makeGrainTile` in `styles/shared/grain.ts` is a good start). `setup` runs again whenever the world gets a new seed, so key any cache by the seed too.
5. **The land.** `drawLayerChunk(ctx, chunk, env)` draws one layer (far range, middle range, hills or ground) over 4 seconds of music. The engine caches the result, so heavy work belongs here.
   - Draw in CSS pixels and multiply sizes by `env.scale`.
   - `env.toX(t)` turns music time into x, `env.toY(h)` turns a ridge height into y.
   - `sampleRidge(chunk, env)` from `styles/shared/ridge.ts` gives the ridge across the whole canvas.
   - Draw past the chunk edges and let the engine clip them. `objectsAround` and `waterAround` include what overhangs from the neighbors.
6. **Randomness.**
   - `env.rng` is for texture that stays inside the chunk. Use it in a fixed order, so a redrawn chunk matches the cached one.
   - Each tree, rock or bird gets its own `createRng(object.seed)`.
   - Anything that runs across a chunk edge (an outline, a wave, a grain pattern) must be a function of music time: the noise helpers in `styles/shared/` do that when given a seed that is the same for every chunk.
7. **Mist and finish.** `drawAtmosphere` runs after each layer (haze between depths) and `drawOverlay` on top of everything (grain, a seal). Both run every frame. `view.clock` is the time for anything that drifts; never read the clock yourself.
8. **The panorama export.** Implement `drawSkyStrip` so the export can draw the sky behind the whole image at once. Without it, `drawSky` is used in tiles. Press `E` to try it.
9. **Look at it with real sound.** Try the landscape on its own, a song, and the mic. Under the mic, near layers are redrawn as sound arrives, and far ranges are frozen when they come into view, at different moments. Anything that crosses a chunk edge must still meet itself.
10. **Tests and screenshots.**
    - `npm run test` already draws every style: every layer, the sky, the mist, and the same chunk twice to check it comes out the same.
    - Add the style to `STYLES` in `tests/e2e/screenshots.spec.ts`, then run `UPDATE_SCREENSHOTS=1 npm run test:e2e -- screenshots` to write its reference screenshots to `docs/screenshots/`.
    - To give it a number key, add it to `STYLE_KEYS` in `src/main.ts`. The Style button steps through the same list.

The paper, ink and ukiyo-e folders are worked examples, each about a thousand lines split into a few files.

## Walkthrough: tune the mapping

The mapping in `src/world/mapping.ts` is where music becomes land, and where Topotone gets its personality. All of it is in one object, `MAPPING`, with comments.

1. **Open the tuning panel.** Add `?tune` to the address, on your machine or on the [live site](https://yodim.github.io/topotone/?tune). Each value has a slider, grouped like `MAPPING`. `T` hides the panel.
2. **Give it music.** Drop a song you know well, or press Mic. Changing a slider rebuilds the land, and your values are kept in this browser until you press Reset.
3. **Know the groups.**

   | Group                   | What it shapes                                                                                          |
   | ----------------------- | ------------------------------------------------------------------------------------------------------- |
   | `context`               | How the mountains read the melody: tone against the mean and spread of the last 30 s                    |
   | `far`, `mid`            | The distant and middle ranges: how much tone, energy and noise lift them, and over how long             |
   | `hills`                 | The foreground hills: height and ruggedness from loudness                                               |
   | `ground`                | The ground under the trees, mostly noise                                                                |
   | `water`, `silence`      | Rivers from sustained bass, and plains or still lakes from long quiet                                   |
   | `grass`, `trees`        | Which onsets plant grass, small trees, large trees and rocks                                            |
   | `crescendo`, `drop`     | A sudden swell (a lone peak or birds), and a swell after a build-up (both, taller, with the hills lift) |
   | `sky`                   | The windows behind the mood, the warmth and the mist                                                    |
   | `pitchWeight` (general) | How much a confident pitch counts against brightness                                                    |

4. **Share what you found.** Copy JSON gives only the values you changed. Open a [mapping idea](https://github.com/yodim/topotone/issues/new?template=mapping-idea.yml) with that JSON, what you heard and what the land did. Please describe the music rather than attaching it.
5. **Change the defaults in code.** Edit `MAPPING`, then run `npm run test`. `tests/musical.test.ts` plays the code-made fixtures through the world and checks that it still reads as music: a rising sweep climbs, a click track plants trees on the beat, a drone opens a river, a silent gap leaves a calm lake, a loud passage is more dramatic than a quiet one, and a drop is marked. If the mapping's behavior changes, update the table in `README.md` too.

Two things to keep in mind. Every window is centred on the time it describes, except under the mic, where it can only look back; the same values can feel different live. And a value is always a function of time, so chunks can be built in any order and still meet exactly.

## Pull requests

- Keep each pull request to one idea, with small focused commits. Say what changed and why in plain sentences.
- For anything you can see, add screenshots: the landscape on its own, a song and the mic, at laptop and phone widths.
- Writing style for docs, comments and commit messages: plain English, short sentences, no hype.
- Run the checks above. The pull request template lists them.

## Bugs and ideas

Open an issue and pick a form: a bug, a new style, or a mapping idea. For a bug, the whole address from the address bar helps most: it holds the seed and the style, so the same world can be brought back.

Looking for something to start with? Try the issues labelled [good first issue](https://github.com/yodim/topotone/labels/good%20first%20issue) or [help wanted](https://github.com/yodim/topotone/labels/help%20wanted).
